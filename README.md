# Pascal Markets

A research scanner for mispricing and arbitrage on Kalshi. It reads Kalshi's public REST API, tests bounded basket combinations with a payout lower bound across outcomes, and records how long each profitable one lasts. It places no orders and needs no account or API key.

## What it looks for

- **No baskets on exclusive events.** At most one outcome of a mutually exclusive event wins, so buying No on all n outcomes pays at least n − 1. Buying Yes on every outcome is not treated as an arbitrage: Kalshi's outcomes need not be exhaustive.
- **Strike-ladder contradictions.** For "above X" markets on the same underlying, Yes at a lower strike plus No at a higher strike always pays at least 1. "Below X" ladders mirror this. Rungs count as the same underlying only when their settlement rules read the same once only the strike comparison is masked, and rungs must close at the same time, and only one-sided strikes qualify (Kalshi tags some "exactly N" buckets as "less").
- **Cross-venue gaps with Polymarket.** For each reviewed pair in `config/pairs.json`, Kalshi Yes plus the opposite Polymarket outcome (and the reverse) pays 1 when both settle the same way. Pairs are added by hand only after reading both sets of settlement rules.

Each basket is sized to the smallest top-of-book size among its legs, capped at `maxContracts`. Its cost includes the Kalshi taker fee, 0.07 × C × P × (1 − P) per order rounded up to $0.0001 ([fee rounding](https://docs.kalshi.com/getting_started/fee_rounding); a demo fill of 1 contract at $0.33 was charged $0.0155), and the Polymarket taker fee where enabled, rounded up to $0.00001 per trade ([Polymarket fees](https://docs.polymarket.com/trading/fees)). Each leg is costed one tick worse (configurable `slippageTicks`) while displaying its seen price. A hit needs at least $1 profit and 3% return by default (`minProfit` and `minReturn`). Series fee multipliers are fetched once per scan. Annualized return divides the return by the time until the last expected expiration.

## Run

Requires Node.js 22.4 or newer, with no dependencies.

```sh
node --test
node src/cli.js scan
node scripts/kalshi-scan.js
node src/cli.js serve
```

`scan` prints the current hits. `kalshi-scan.js` also updates the tracked hits in `research/kalshi/`.

## Dashboard-controlled scanning

Double-click `scripts/open-dashboard.cmd`. The dashboard opens idle. One **Start engine / Stop engine** button controls the session. **Start** launches one market-data loop, which is also the quoting engine's paper loop (`kalshi-gameday.js --dashboard --feed --until=never --out=data/maker`), and beside it every paper agent in `PAPER_AGENTS` (`src/dashboard-runner.js`): game-watch and station-watch on `--budget=split`, reward-maker, longshot-watch, score-watch and the nightly rebalance. Each agent logs to `data/paper/<name>.log` and `<name>.err.log`; one that exits is reported in the runner's `agentErrors` and is not restarted. Repeated clicks cannot launch a second copy. **Stop** ends the loop with its feed, scans and dry-run subprocesses, and every agent. Closing the last dashboard window stops all of it after the 20-second reconnect grace period, so the week's paper test runs only while a dashboard window stays open. Opening the dashboard again requires Start again. Stopping preserves the last displayed results. The desk includes recorded basket-edge and latency charts, opportunities, dry-run trade history, and model positions from the saved market-making report. Model P&L is marked simulation inventory; dry-run availability checks do not create account positions. The account positions panel states when account sync is unavailable. Telemetry reads are bounded to the tail of local logs so large recordings do not block the dashboard.

Start selects the production WebSocket feed when `KALSHI_KEY_ID` and `KALSHI_KEY_PATH` are configured; otherwise the 15-second REST watch list is used. Full discovery runs every five minutes. The first discovery can take several minutes. Results and rounds from dashboard sessions are saved under `data/maker/` (under `data/dashboard/` before Nov 13).

The GitHub workflow has no scheduled trigger. A manual archival scan remains available under Actions → Kalshi scan → Run workflow. Explicit command-line scans remain available for research.

## Dry run

New hits in the active loop are checked against public prices after `dryRunDelayMs`. The outcomes filled, missed and legged describe observed price and size availability; they do not establish a real execution. Local records stay in `data/maker/dryrun.jsonl`.

## Limits

- Depth is top of book only. Larger sizes walk the book and cost more.
- A hit seen between two scans may already be gone. Lifetime observations are separated by the actual scan cadence; continuity between observations is not established.
- Money is locked until settlement, which the annualized figure accounts for only roughly.

## Results and market-making research

`node scripts/kalshi-report.js [dir]` summarizes hit episodes, lifetime bounds, dry-run outcomes and the latest near-miss buckets. `node scripts/kalshi-mm-sim.js [dir]` simulates one-contract quotes from the last `mm.replayDays` (3) days of `books.jsonl`. The default directory is `research/kalshi`. Both scripts write Markdown and JSON reports; manual workflow runs publish these artifacts and book snapshots.

`node scripts/kalshi-history.js [--days=60] [--min-volume=1000] [--window-hours=48] [--rate=8] [--max-markets=N] [--out=data/history]` backfills settled binary markets from Kalshi's public API into one folder per UTC day, newest day first and most-traded markets first. Candles come from Kalshi’s batch endpoint, several markets per request (up to 100, and at most 10,000 candles per request, so about three 48-hour markets, usually siblings of one game); each market is cut to its own window, which matches a single-market request exactly. This made the download about 70% faster at the same request rate. Combo (multivariate) markets and markets below the volume floor are skipped. Each market gets one-minute candles from its last `--window-hours` as `books.jsonl` rows in the live recorder's format, keeping only changed books plus a 15-minute heartbeat. Candles carry no depth, so sizes are a nominal one contract. Public trades go to `trades.jsonl`, but only for markets that ever showed a quotable spread (three ticks or more inside the mid band) before the `mm` pull time, and only up to that time. Live-game tapes, which make up most of Kalshi's volume, can never fill a model quote. `markets.jsonl` marks finished markets, so a stopped run resumes where it left off. `settlements.json` holds each $1/$0 outcome. Kalshi moves markets settled before its historical cutoff (2026-09-11 at the time of writing) to separate endpoints this script does not read. `node scripts/kalshi-mm-sim.js data/history/<day> --history` replays one backfilled day in full, with quote and markout limits widened to the candle spacing.

`node scripts/kalshi-bandit.js [data/history] [--final]` tests a learned quoting policy (`src/bandit.js`), a contextual bandit. For every snapshot and side the fixed rules would quote, it records the closing-line value that one-contract quote would have earned: the last mid before quoting stops minus the price and maker fee when a crossed book or a public trade fills it, and 0 otherwise. Settlement is not the reward: it swings each contract by its whole price, about 20 times the edge being learned. Rewards are grouped by context: side, price decile, spread, hours to the pull time, and the 15-minute price move against that side, at three levels (coarse, general, per series). All markets of one event (a game or a release, keyed by the ticker’s second segment, so every series of one game counts together) count once per context. Estimates are shrunk toward zero edge and then toward the coarser level, with a prior worth ten events. The fixed rules stand by default: a quote is declined only where at least 30 earlier events back its context and the estimate is negative. The policy can only decline quotes the fixed rules allow; the pull times, jump halt, mid band and inventory cap still apply. Days are walked forward: each day is traded by a model trained only on days at least two before it (a day folder holds markets that close that day, and quoting starts up to 48 hours earlier, so the day just before overlaps it in time), compared with the fixed rules on the same day, and then learned from a day later. Once 20 days exist, the newest 10 are a locked final exam, run only with `--final`, once, at the end. The report gives fills, closing-line value and settled P&L with 90% ranges that resample whole events (`src/stats.js`), the learned-minus-fixed difference paired by event, a capacity figure (contracts traded at or through each filled quote times that fill’s closing-line value, an upper bound that assumes first place in the queue), and Gate 0: closing-line value above zero across its range with settled P&L not significantly negative. The simulator reports the same closing-line value and per-fill records (`clv`, `fillLog`). The script writes `bandit-report.md`/`.json` and the model trained on all days, `bandit-model.json`, into the history folder. At least three backfilled days are needed. The reward ignores inventory skew, and candle books have no depth, so the results compare policies rather than forecast live fills.

`npm run model` (`node scripts/kalshi-model.js [--wait]`) runs that walk-forward once the history download is complete. It checks that `data/history/backfill.log` ends with the backfill’s finished line, makes one more resumable backfill pass if any market failed (usually Kalshi rate limits, listed in `backfill.err.log`), reaching back to the oldest day folder so no early failure is skipped, and stops without a model if that pass still cannot list a day, then runs `kalshi-bandit.js data/history` and the history tests below, each on its own, so one failure does not stop the rest, then the walk-forward picker (`agent-tune.js`) and the department leaderboard. With `--wait` it checks every 10 minutes until the download finishes; a log with no new line for 3 hours counts as a stopped download and ends the wait with an error. It never runs the locked final exam.

**Focus since Nov 12.** Four strategies are kept: game-watch, station-watch, the quoting engine and longshot. On the downloaded history (trades from Sep 12 to Nov 1; the newest 10 days stay locked) the history tests showed, per contract: station-watch +12.4¢ (227 trades), game-watch +7.7¢ (3,195), the learned quoting policy +1.4¢ (50,606 fills, +$723) and longshot +1.4¢ (22,178, failing on closing-line value). The rest are dropped: the sportsbook taker and its live gap-taker (+3.0¢ on 381 trades, range across zero), the weather forecast taker (−5.7¢), the weather maker (−0.2¢) and cross-venue (+2.4¢ but 26 hedges, $0.63 in 60 days). Their code and results stay in the repository; the model run no longer runs their tests, the leaderboard leaves them out, and the odds logger and gap-taker no longer run. `agent-sportsbook.js` still runs in the model run, because it builds the ESPN game cache that game-watch's history test matches games through.

`node scripts/odds-log.js [--minutes=5] [--books-markets=h2h] [--books-lead=60] [--books-spacing=120] [--books-daily=15] [--books-soccer-daily=6] [--once]` logs sportsbook lines for the sports Kalshi lists, as raw American odds in `data/odds/<UTC day>.jsonl`, for the sportsbook price checks still being built. ESPN’s public scoreboard provides DraftKings moneyline, spread and total for today and the next two days, free, every 5 minutes. It covers the US leagues and 20 soccer leagues, chosen by Kalshi volume (Champions, Europa and Conference League, the top five European leagues, the Championship, Brazil, Argentina, Liga MX, MLS, Colombia, Paraguay, Peru, Japan, Turkey, Portugal and the Netherlands). Soccer moneylines are three-way, home, away and Draw; a game whose draw price is missing logs no moneyline rather than a two-way one. Setting `ODDS_API_KEY` adds Pinnacle, DraftKings, FanDuel, BetMGM, Caesars, ESPN BET, Fanatics, BetRivers, Bovada and BetOnline through The Odds API. Its credits are spent where they count: a league is swept only when one of its games starts within the lead time, at most once per spacing, and never past the daily credit cap. Soccer gets the twelve highest-volume of those leagues and at most its own share of the cap, since its morning kickoffs would otherwise spend the day's credits before US evening games. Each market type costs one credit per league sweep, so the defaults fit the free plan’s 500 credits a month. Pregame lines are the sharpest, and pregame is when Kalshi trades most before a game, so busy days such as NFL Sundays get several sweeps and empty days cost nothing. The logger stops calling the API below 20 remaining credits. The key is read from the environment and never logged. The logger never calls Kalshi, so it does not share Kalshi’s rate budget. Sportsbook websites are not scraped. Research only; nothing is bet or ordered.

Four taker agents test fair-value trading on the same history. Each buys one contract of the side its fair value favors, at the posted ask (Yes) or one minus the bid (No), only when the edge after the taker fee beats `--margin` (1¢), and holds it to settlement. Each reports settled P&L with 97.5% ranges that resample whole events (several agents are tested, so the range is wider than the bandit's), the mean squared error of its fair value against Kalshi's mid at the same moment, and a gate: settled P&L above zero across its range. All keep the newest 10 days locked unless `--final`, and write `<history>/agents/<name>-report.md`/`.json`.

- `node scripts/agent-sportsbook.js [data/history] [--fetch-only]` (Agent A): game markets against DraftKings' closing moneyline, margin removed, from ESPN's public API (`src/agents/fair-odds.js`). It covers the US leagues and 20 soccer leagues; a soccer line is three-way (home, away, draw), Kalshi's soccer tickers list the home team first, and since their team codes often differ from ESPN's (BRI for BHA, VDG for VAS) a soccer team also matches on its name or initials, while each game's TIE market is priced from the draw. Closing lines for every date in the history are fetched once into `data/odds/espn-closing.jsonl`, resumable, with no Kalshi requests. Each Kalshi ticker is matched to one ESPN game by Eastern date and team codes (spellings differ, such as NYK and NY); a match one day off or with the teams listed the other way round needs both codes to agree closely, and ties are skipped, never guessed. Markets are read at the game start.
- `node scripts/agent-game-watch.js [data/history] [--lag-seconds=60] [--margin=0.01]` (game-watch, run after Agent A, whose ESPN game cache it reads): did Kalshi keep selling a market cheap after the game had already decided it? NBA, NFL, NHL, college football (FBS and FCS) and college basketball (Division I; women's game totals only, the one women's "N or more" market Kalshi lists). These can only go up: game totals, team totals, quarter, half and period totals, NBA player points, rebounds, assists, threes and points+rebounds+assists, and NHL player goals. So the play that takes one to its line decides Yes (`src/agents/game-watch.js`). ESPN's log ends every game with an end-of-game play at the final whistle ("End Game" in basketball, "End of Game" in hockey and football; in 341 of 344 cached games its score is the final). That play also decides winners, spreads (`KXNBASPREAD-...-LAC10` pays when LAC wins by 10 or more; on Nov 3 to 7 all 789 NBA and 216 NHL spreads settled that way on ESPN's final), and No on game and team totals still short. A half or quarter total still short is decided No when a later period starts, but only for periods that end before the last regulation one, since those counts leave overtime out. An event code is matched only when the game's two team codes spell it well: on the sample days the weakest fits were a different game four times in ten (Bellarmine at Indiana read as BEL + LIND and matched to CBBL at LIN), and a team's side must agree with where its code sits in the event code. Some markets are left out:
  - NFL player yards, since a play that loses yards takes them back.
  - NHL assists and points. The league often changes assists after the game, and on the sample days three assists ESPN credited settled No.
  - Hockey games settled in a shootout.
  - Overtime points in half and quarter markets. Whether Kalshi counts overtime in a college half was not checked, and leaving it out can only undercount, so a line reached without it is reached either way.

  ESPN's free play-by-play gives each play's wall-clock time; each game is fetched once into `data/sports/` (ESPN only, never Kalshi). Some time after the deciding play, the decided side is bought, one contract held to settlement, at the first 1-minute candle closing after that moment whose edge after the taker fee beats the margin. Only later candles count: a decided market often has no Yes offer left, and the history keeps no row for such a minute, so an earlier candle would be a price from before the play. A player whose play-by-play tallies disagree with ESPN's box score is skipped, and so is a game whose play log does not end on the final score. Score corrections (an overturned basket, a free throw logged out of order) count against the total. The report repeats the test at 15 seconds to 10 minutes. On the 4 sample days (Nov 4 to 7) it found 683 trades 60 seconds after the play, +$33.25 (range +$21.06 to +$50.01), with one wrong call. Most bought at 94–98¢: NBA rebounds and assists, and 80 NHL goal markets (+$3.96). College football gave 67 trades (+$12.76) men's college basketball 2 (+$0.69) and women's 4 (+$0.71): Kalshi had already priced out 795 decided men's totals within the minute, and NFL scores gave one trade. The wrong call came from ESPN's feed, not the game: Buffalo at Miami (OH), Nov 3, showed Miami (OH) at 30 and then 37 on a run and a timeout, points that never happened, and the team-total market bought at 34¢ on them settled No (−$0.36). Football scores often appear a row before their scoring play, so counting only scoring plays would have cut college football to 10 trades (+$1.01); every row counts, and the risk is accepted. Buying 15 seconds after the play gave +$59.86 and 10 minutes after +$8.12. The final whistle decided 12,226 markets in all, but Kalshi prices a final out within seconds: buying at the end-of-game play itself gave 73 trades (+$5.79), 15 seconds later 16 (+$1.52) and a minute later 9 (+$0.70), all with no wrong calls. The candles are one contract deep, so size is not tested, and one wrong call costs about as much as 40 wins.
- `node scripts/agent-longshot.js [data/history]` (Agent C): the favorite-longshot fade, walked forward (`src/agents/longshot.js`). Each market is read an hour before quoting would stop. A day is traded by price-bucket rules learned from days at least two earlier, only where 30 earlier events back the bucket. It also reports a calibration table (how often Yes won in each price bucket) and closing-line value, which its gate also needs above zero.
- `.venv/Scripts/python -I scripts/becker-longshot-samples.py [hours]`, then `node scripts/becker-longshot.js [hours]`: the same walk over four years of the Becker dataset (July 2021 to Nov 24, 2025, so none of it overlaps the downloaded history). The dataset has trades but no books, so a market is read H hours before close from its last buyer-taken trade (the ask) and last seller-taken trade (the bid) in the hour before; markets without both, about 83% of the 214,042 with at least 1,000 contracts traded, are left out. Today's taker fee is charged in every year. Read 2 hours before close (35,585 markets), the walk made 1,065 trades and lost $21.68 settled (−$52.08 to +$9.67) and $57.65 on closing-line value (−$72.67 to −$43.36), with every year negative. At 6 hours it lost $8.69 and at 24 hours $25.25, and Gate C failed each time. The calibration shows the textbook bias, smaller than the costs of trading it: 5–10¢ contracts won 6.2% of the time at an average price of 7.2¢, and 95–98¢ ones 97.8% at 96.4¢, about a cent each way, which the taker fee and the spread more than cover. Learned from all four years, no bucket earns a rule at 2 or 6 hours, and only 95–98¢ Yes does at 24 hours. Results go to `data/becker/longshot-report-<H>h.{json,md}`.
- `node scripts/agent-weather.js [data/history] [--series=A,B]` (Agent D): daily high and low temperature markets against a day-ahead forecast (`src/agents/fair-weather.js`). Strikes and the settlement station come from Kalshi's settled-market listings (paced at one request a second, so best run after the download), readings from the NWS climate reports through the Iowa Environmental Mesonet, and the forecast from Open-Meteo's previous-runs archive (what the models said a day earlier). Each station's bias and spread come from its own last 30 reported days up to two days before the target date. Markets are read at 04:00 UTC on the target date, the evening before in the US: by mid-morning the overnight low is in and Kalshi has seen it. A series whose readings disagree with Kalshi's results on more than 10% of markets is left out. Downloads are cached in `data/weather/`.
- `node scripts/agent-station-watch.js [data/history] [--lag-minutes=30] [--index | --no-index]` (station-watch, run after Agent D, whose caches it reads): did Kalshi keep pricing a temperature range after the station's readings so far had already decided it? A station's official high can only rise from its readings so far and its low only fall, so a range below the high so far (or above the low so far) cannot pay. Readings come from the Iowa Environmental Mesonet: the 5-minute reports most stations send (whole degrees Celsius, read from the METAR's T group) and the hourly ones (tenths); Central Park sends hourly only. Error codes (-61°C) and lone spikes are dropped. A cushion of 1° on highs and 2° on lows covers the difference from the climate report (`src/agents/station-watch.js`): on 1,027 station-days the report's high was never more than 1° below the highest reading, and its low was more than 2° above the lowest reading once (Miami, Sept 28, where the report disagrees with an hour of steady readings). Each market's books are walked in time order with readings taken at least the lag earlier, and the decided side is bought at the first book where its edge after the taker fee beats the margin. Decided ranges that settled the other way are reported as wrong calls. **Speed decides it.** On Sept 21 to Oct 31, Kalshi priced a decided range out 15 to 20 minutes after the reading: acting 5 minutes after a reading made 358 trades (+$45.48, range +$36.73 to +$55.50), 15 minutes 135 (+$19.81), 20 minutes or more about 4 (+$0.08), all with no wrong calls. The free feeds deliver the 5-minute readings 24 to 27 minutes late (the Mesonet) or 37 (the weather service's API), so the default lag is 30 minutes and, with these feeds, the strategy finds almost nothing. Kalshi's own public city temperature index (`/live_data/weather/{city}?detailed=true`, no key) carries each member station's 1-minute reading about 2.4 minutes after the minute, for twelve settlement stations (Midway, DFW, Boston, Houston, LAX, Miami, Minneapolis, Philadelphia, Trenton, Seattle, SFO, Newark). The test adds those readings, each counted from the moment Kalshi received it, with one request per city and climate day cached as `data/weather/kidx-<city>-<date>.json`. It skips them while the history download runs (`--index` reads them anyway, `--no-index` never). On Oct 19 alone they gave 5 trades (+$0.35, 4 from the 1-minute feed, no wrong calls), against 4 trades in the whole history at the 30-minute lag. The hourly and special METARs (the readings off the 5-minute grid) reach aviationweather.gov's free feed a median 3.5 minutes after their time (90% within 4.6, Nov 12), so since Nov 12 they count 5 minutes after their time (`--metar-lag-minutes`). On the downloaded days that made 285 trades (+$35.85, range +$27.57 to +$44.70, no wrong calls) against 227 (+$28.19) with every Mesonet reading at 30 minutes. The twelve stations outside Kalshi's index (Austin, Denver, Central Park, Atlanta, Washington National, Las Vegas, New Orleans, Oklahoma City, Phoenix, San Diego, San Antonio, Louisville) went from 3 trades to 48.
- `node scripts/agent-weather-maker.js [data/history] [--margin=0.02] [--lag-minutes=30] [--sims=400] [--max-position=3] [--bucket-minutes=15] [--weight=1]` (weather-maker, run after station-watch, whose caches it reads): would resting bids on both sides of each temperature range, priced by a Monte Carlo day model, have made money? The model (`src/agents/weather-mc.js`) simulates the rest of the climate day by replaying, from each of the station's previous 30 days, how far the hourly forecast issued a day earlier (Open-Meteo's previous-runs archive, cached as `data/weather/forecast-hourly-*.json`) missed that day's extreme over the hours still left, and how far the climate report sat from the readings. The latest reading's distance from the forecast moves the simulated day, fading by the station's hour-to-hour error persistence. The readings so far bound the result. The share of simulated days a range pays is its fair price, and `--weight` blends it with Kalshi's mid. Bids rest at or one tick inside the touch where fair value beats price plus the maker fee by the margin. A bid fills when a later recorded trade sells through it, at its price when it improved the touch, or when the book crosses it, one contract per side per book row, held to settlement. The same prices drive a one-contract taker and an accuracy check against Kalshi's mid at 4, 16 and 20 UTC. Over 360 station-days in October the model's high was 0.3° low on average and its low 0.1° low, with the result inside the 10–90% band 86% and 82% of the time. Against Kalshi it trails. On the Oct 20 markets its squared error was 0.174 at 4 UTC against Kalshi's 0.135, the maker lost $34.06 on 1,707 fills and the taker lost $17.47. Even a quarter-weight blend with the mid was less accurate than the mid alone. The forecast is a day old while the market sees the latest runs and readings, so the model adds nothing on that day.
- `node scripts/agent-crossvenue.js [data/history] [--margin=0]` (Agent F): the same game on Kalshi and Polymarket US, the CFTC-regulated exchange open to US accounts. The international polymarket.com, which the scanner reads, is closed to US accounts. A hedge buys one team on each venue, so exactly one leg pays $1. It counts when the two asks plus both taker fees (Kalshi 0.07, Polymarket US retail 0.095, `src/agents/cross-venue.js`) cost less than $1. Polymarket US’s public price history stores its best asks about once a minute, so every Kalshi minute in the 24 hours before the start is compared with the Polymarket US asks at most 90 seconds older. Games are matched by Eastern date and team codes from Polymarket US slugs (`aec-nba-phi-det-2026-11-04`). A game whose venues settled differently is left out. One contract per game is counted, at the first profitable minute. The history has prices but no sizes, so the result shows whether gaps beat the fees, not how much could be traded. Listings and histories are cached in `data/polymarket-us/`, and no Kalshi requests are made.
- `node scripts/agent-tune.js [data/history] [--min-events=10] [--objective=low|ratio]` (the walk-forward picker, run after game-watch and station-watch, which write a settings grid: each market at margins of 1, 2, 3 and 5¢): for each market group (a series, and for game-watch its side), which margin has the highest low end of the profit range in dollars, chosen each day from the days before it only (`src/tuner.js`). Profit-to-risk is the low end of the 97.5% profit range, resampling whole events (a game, or a station's day), divided by the money staked. Ranking by dollars favors more trades at a thinner return, which grows total profit; `--objective=ratio` ranks by profit-to-risk instead. A group runs nothing on a day when no margin scores above zero on at least 10 earlier events. The report compares the walk with every group at 1¢ on the same days and lists each group's next setting: a margin, `off` when at least 10 events show none that pays, or `default` when the history is too thin. A group's pick (a margin or `off`) stands only where the walk made more in dollars than 1¢ did in that group on the same days; elsewhere the group runs 1¢. The live game-watch and station-watch read these picks. On the 4 sample days the picker made $4.62 against $27.97 at a fixed 1¢. It could act only once a group had 10 earlier events, and by profit-to-risk it chose 5¢ for NBA rebounds and assists and NHL goals: fewer trades with a fatter return each (rebounds: 25 trades, $2.91, against 271 and $7.75 at 1¢). Ranked by dollars, the default since Nov 12, it made $7.12.

`src/takers.js` holds the shared taker rules and scoring, and `src/history.js` the history-day listing (`historyDays`) and line reader (`jsonLines`) that the bandit and agents share.

### Departments

The work is split into seven departments: arbitrage between markets, weather, economics and Up/Down, politics, sports US (with college sports), international soccer, and everything else. `config/departments.json` assigns each Kalshi series to exactly one of them by ordered patterns, drawn from the 2,971 series in the 60-day history; anything unmatched lands in everything else, mostly tennis, esports, golf and mention markets. Arbitrage owns no series: the cross-venue agent's hedges count there whatever their sport. `src/departments.js` holds the classifier, the scoreboard and the on/off switches.

`node scripts/departments-report.js [data/history]` reads the saved trades of every history test (the bandit's fixed-rules quoting, recorded per market, and agents A, C, D and F) and writes `departments-report.{json,md}`: per department, trades, settled P&L with its 97.5% range grouped by event, the newest day, the last 7 calendar days, the share of the $1,000 weekly target, closing-line value where an agent records it, the gate, and each agent's part. An agent whose report is missing is listed, not guessed. `npm run model` runs it last.

The dashboard's leaderboard panel shows that report, ranked by settled P&L, with one checkbox per department. A switch is saved in `config/departments.local.json` (gitignored), so it survives a restart, through the same guarded local control as Start and Stop. No department places orders yet; the switches take effect once the paper-trading loop exists.

Each department also lists its agents in `config/departments.json`, from a shared catalog that marks every agent as research or trading and as built or planned. Clicking a department's name opens its page (`GET /api/departments/<id>`): every agent with its current state, last action and history-test result, an activity feed of the newest 40 reports, and the department's 25 newest history-test trades. Built agents report through `src/heartbeat.js`, which appends `{time, agent, state, detail, nextBy}` rows to `data/agents/<agent>.jsonl`: the odds logger after every sweep (`books-espn`, `books-oddsapi`), and the model run while it waits for the download, queues and runs each history test (`maker`, `sportsbook`, `longshot`, `weather`, `crossvenue`). An agent whose next report is past its `nextBy` time shows as overdue rather than healthy. The live engine's state comes from the engine itself, and a planned agent shows as planned.

`node scripts/gap-taker.js [--wait] [--minutes=5] [--margin=0.01] [--lead-hours=12] [--series=KXNBAGAME,...] [--once]` is the live gap-taker, the first paper-trading agent: Agent A run continuously instead of once at kickoff. Every pass it prices each Kalshi game market (US sports and the 20 soccer leagues) whose game starts within the lead time from the freshest line the odds logger wrote in the last 15 minutes, Pinnacle when it has one and DraftKings otherwise, margin removed (`src/agents/gap-taker.js`). Every side whose edge after Kalshi's taker fee beats the margin is bought on paper, one contract per game, held to settlement; the price may be anything, so 1¢ on Kalshi against 10% at the books is taken. Markets the two books disagree on by more than 5¢, markets with nothing offered at the price and games already started are skipped, and an edge above 15¢ is logged to `data/paper/gap-flags.jsonl` for a rules check rather than taken, since gaps that large usually mean a different bet or a stale line. Departments switched off on the leaderboard are skipped. Trades go to `data/paper/gap-taker.jsonl` and, once Kalshi settles them, their results to `gap-settled.jsonl`; each department page lists its paper trades with their P&L. Kalshi is read through its public API only, with no key and no orders. The history download uses all of Kalshi's request limit, so with `--wait` the gap-taker holds off until the download and its retry pass are done.

`node scripts/station-watch.js [--minutes=10] [--every-seconds=30] [--margin=0.01] [--force] [--once]` is the live station-watch, the weather department's paper agent. Every 10 minutes it reads each Kalshi weather station's 5-minute and hourly readings on its last two climate days from the Iowa Environmental Mesonet (no key, no Kalshi requests), in the background so it never holds up the faster feed, and reports on the department page. Once the history download is done (`--force` skips that check), every 30 seconds it also reads the 1-minute readings in Kalshi's city index for the twelve stations it covers. Every minute it reads the hourly and special METARs for all 24 stations from aviationweather.gov in one request (no key, about 3.5 minutes late), the fastest feed for the twelve outside the index. Kalshi's open KXHIGH and KXLOW markets are listed every 5 minutes, and each pass reads fresh prices for just the ranges the readings have already decided, 50 to a request; a pass after the first takes about 4 seconds. It buys on paper, held to settlement, the side of any range the readings have already decided, when its edge after the taker fee beats the margin and something is offered at that price: as many contracts as are offered, up to 25 a market (`--contracts`) and 25 across one series' day (`--per-day`), since one bad reading can turn every range of that day. Each series runs the margin the walk-forward picker chose, `--margin` where the history was too thin to say, and none where it found no margin that pays. The size offered is saved with each trade. Trades go to `data/paper/station-watch.jsonl` and results to `station-settled.jsonl`, through the same ledger as the gap-taker (`src/paper.js`). Stations and series come from Agent D's caches in `data/weather/`.

`node scripts/longshot-watch.js [--every-seconds=60] [--list-minutes=15] [--force] [--once]` is the live longshot (Agent C), a paper agent across every department. Every 15 minutes it lists Kalshi's open events (about 107 pages, a minute at 3 requests a second), and every minute it reads fresh prices for the markets that have traded at least 1,000 contracts and are in the half hour up to an hour before quoting would stop, the moment the history test reads them (`liveTrade` in `src/agents/longshot.js`). A market whose price falls in a bucket with a rule is bought on that side, one contract, held to settlement. The rules are the history test's `next` rules, learned from every day read; on Nov 12 they were buy Yes at 5–10¢ and at 2–5¢. On 60 days the walk made +$310.87 settled (+$182 to +$453) on 22,178 trades, nearly all from 5–10¢ Yes, but −$273.41 on closing-line value, so Gate C fails, and the 2–5¢ rule lost $13.85 in the walk. Four years of Becker data contradict the 5–10¢ Yes rule: there those contracts won less often than their price, and buying them 24 hours before close lost $4.85 on 391 trades. It runs on paper to see which score holds. It has no circuit breaker, since most of its trades lose by design. Trades go to `data/paper/longshot.jsonl` and results to `longshot-settled.jsonl`.

`node scripts/score-watch.js [--every-seconds=10] [--margin=0.01] [--contracts=25] [--budget=off] [--hold-seconds=60] [--daily-loss=50] [--force] [--once]` is score-watch, game-watch's idea for tennis, soccer, esports and table tennis. Kalshi's own public live data (`GET /milestones` links each match to its events; `GET /live_data/batch` gives the scores, 100 matches a request, no key) carries set-by-set tennis scores, goal-by-goal soccer scores, map-by-map esports scores and set-by-set table tennis scores for every match it lists, including the Challenger and ITF events ESPN does not carry. Every 10 seconds the agent reads the matches under way and buys on paper, held to settlement, any market the score has already decided (`src/agents/score-watch.js`):
- **Tennis.** A finished set decides both set-winner markets, a games total passed decides Over, and an exact set score the other player has already beaten decides No. Match winners, games spreads, games-total Unders and the remaining exact scores wait for a normal finish, since on a retirement Kalshi settles only what completed play decides and prices the rest. A match tiebreak in place of a deciding set counts as one game.
- **Soccer.** Totals, team totals, both teams to score and first-to-score are decided by goals; first-half markets at half time; results, spreads and exact scores at full time, on the regulation score (Kalshi counts 90 minutes plus stoppage time). A soccer decision must hold for a minute before it trades, since a video review can take a goal back, and a match in extra time without its regulation score decides nothing.
- **Esports.** In a CS2 or Dota 2 series a finished map decides both map-winner markets, the series is decided once a team has the maps needed (two in a best of three), total maps are decided once passed or once the series ends, and a map spread is decided No as soon as it can no longer be covered. eSoccer and eBasketball winners wait until the game is complete; an eSoccer draw decides its tie market, while an eBasketball tie decides nothing, since Kalshi settles it at 50¢. Any forfeited map decides nothing, since a forfeit before play settles at a fair price.
- **Table tennis.** Liga Pro match winners (about 14 matches an hour) are decided once a player has the sets needed and Kalshi's feed names the same winner.

Each score change is logged to `data/scores/<day>.jsonl`, so a history test can follow once a few weeks are logged; until then, the paper trades are the test. On its first evening (Nov 12) it read 11 to 12 tennis and 8 soccer matches a pass in about 0.2 seconds and called its first decided markets (Over 0.5 goals after a goal) correctly, already priced out at that moment. Trades go to `data/paper/score-watch.jsonl` and results to `score-settled.jsonl`. It runs outside the $2,000 split below.

`node scripts/score-lag.js [day ...]` measures how fast Kalshi reprices after its own live score decides a market (`src/score-lag.js`). For each moment the score log first shows a market decided (a match or game over, a tennis set, an esports map, a soccer goal passing a total), it reads the market's public trade prints from 5 minutes before to 15 minutes after and reports, by sport, the seconds to the winning side's last print under 97¢ (negative when the market moved first), the seconds to a 99¢ print, and the contracts takers still bought on the winning side below 99¢, with their edge after the fee. It writes `data/scores/lag-report.{json,md}`; markets not yet settled wait for a later run. The first run (Nov 12, about 20 minutes of log, 7 settled markets from two ITF matches, one WTA set and one soccer goal) found the market ahead of the feed every time: the winner already traded at 99¢ when the log saw the result, its last print under 97¢ came 18 to 112 seconds earlier, and no taker bought the winner below 99¢ afterwards. Up to about 17 seconds of that is the agent's own polling. If more days agree, Kalshi's live feed is too slow to trade on, and score-watch's paper trades will stay near zero.

**In-play soccer totals (Nov 13).** `src/agents/soccer-inplay.js` prices Kalshi's total-goals markets during a match. **Nightly rebalance (from Nov 13).** `node scripts/rebalance.js [--every-minutes=5] [--once]` runs with the other paper agents under Start engine. `node scripts/reward-maker.js [--markets=40] [--size=10] [--candidates=200] [--max-inventory=30] [--toxic-limit=1] [--every-seconds=60] [--list-minutes=30] [--force] [--once]` is the reward-maker, a paper agent for Kalshi's Liquidity Incentive Program, which pays resting orders whether they fill or not.

- **The program (checked Nov 12):** 6,619 programs, about $143,000 a day in pools. Each covers one market for up to 31 days, usually about 7, and is listed on the public `GET /incentive_programs` with `period_reward` in hundredths of a cent.
- **Scoring:** almost every program sets a Target Size of 1,000 contracts and a discount factor of 0.5 a tick.
  - Kalshi takes a snapshot of the book every second. The first Target Size contracts on each side share that side's score by size.
  - Orders at or better than the Reference Price (where the side's cumulative size reaches a fifth of the target) score in full, and each tick worse halves the score.
  - A snapshot pays only when both sides hold the Target Size, and a program that ends with under $1 earned pays nothing.
- **Choosing markets:** every 30 minutes it lists the active programs and reads the books of the 200 best-paying markets. It keeps the 40 where a 10-contract bid at each side's Reference Price would earn the most.
- **Each minute:**
  1. Fills come from the exchange-wide trade tape. A trade at the bid's price first works through the contracts ahead of it in line, and one through its price fills it outright.
  2. The bids that rested through the interval are scored on the fresh book as one snapshot and credited for the time since the last pass.
  3. A bid that no longer scores in full moves to the new Reference Price, at the back of that price's line. The line ahead of a bid only shrinks as the level thins.
- **Positions:** fills are held to settlement with the maker fee charged. A market stops bidding a side once its net position reaches 30 contracts that way.
- **Toxicity stop (Nov 13):** an event, meaning every strike of one market (all of one movie's Rotten Tomatoes thresholds, say), stops being bid once its fills have lost more than its rewards paid by over `--toxic-limit` dollars ($1). Fills are valued at the outcome once settled and at the Yes mid until then (`toxicEvents` in `src/agents/reward-maker.js`). Its bids are cancelled, and it is skipped when markets are chosen.
- **First four hours (Nov 12, 21:29 to Nov 13, 01:35 UTC, 10 contracts a side):** rewards accrued $6.80 and the 57 fills cost $4.03 at the mid or settled, for +$2.77 net, about $16 a day on about $500 of cash held. Losses sat in two events. One movie's Rotten Tomatoes ladder, bid on six strikes, lost $4.44 on 30 fills against $1.10 of rewards, and a Trump nominations count lost $1.52. Every other event was net positive. The stop would have blocked those two. Four hours are far too few to tune the $1 limit; it is a loss guard, not a fitted rule.
- **First reading:** in one snapshot of the 400 best-paying books, 10 contracts a side would have earned about $72 a day and 100 contracts about $624, before fills. Those markets are mostly politics, entertainment and review-score markets, where informed traders pick off resting orders, so fills are the cost this agent measures.
- **Sports:** the 182 sports programs are season-long props, not the game markets the quoting loop trades.
- **Files:** fills go to `data/paper/reward-maker-fills.jsonl`, and orders, rewards earned, outcomes and marks to `reward-maker-state.json`.

`node scripts/game-watch.js [--every-seconds=10] [--margin=0.01] [--force] [--once]` is the live game-watch, the sports department's paper agent. Every 10 seconds it reads ESPN's NBA, NFL, NHL, college football and men's and women's college basketball scoreboards and the play-by-play of each game in progress or just finished (free, no key, no Kalshi requests), four games at a time. The summary's plays are topped up with the newest plays from ESPN's core API, which runs ahead of it: on Nov 11 its newest NBA play was 7 to 35 seconds old while the summary's was 23 seconds to 15 minutes. Player markets are still checked against the summary's box score, for the plays it covers. A finished game is read once. It reports how far behind the newest play the feed runs. Once the history download is done (`--force` skips that check), it lists Kalshi's open winner, spread, total, team-total and player markets every 2 minutes and, each pass, reads fresh prices for just the markets the plays have already decided (a line reached, or the end-of-game play; `src/agents/game-watch.js`), 50 to a request. On paper it buys the decided side, held to settlement, when the edge after the taker fee beats the margin and something is offered on that side: as many contracts as are offered, up to 25 a market (`--contracts`). `--per-game` can cap contracts across one game's markets, best edges first; it is off by default. The size offered is saved. Each series and side runs the margin the walk-forward picker chose (`data/history/agents/tune-report.json`), `--margin` where the history was too thin to say, and none where it found no margin that pays. Paper fills assume every offered contract is had at the shown price, which other buyers make less likely with real orders. Price and fee are per contract, and settled results count every contract (`src/paper.js`). Trades go to `data/paper/game-watch.jsonl` and results to `game-settled.jsonl`. A first pass that evening, with seven games in progress, checked 2,757 markets and found 233 already decided. It made 11 paper trades, mostly rebounds and assists at 98¢, with 85 to 200 contracts offered on most.

**Half and quarter totals (fixed Nov 13).** The first live day bought 51 half and quarter totals (first-half team totals, first-half, first-quarter and second-quarter totals), and Kalshi settled 49 of them the other way, about −$35 once they settle. Player props on the same day went 72 for 72. The agent summed ESPN's play log, which does not always match the line score Kalshi settles on: DET at WSH's log ended the first quarter at 67 points, the line score at 65. These totals are now decided only once their periods are over, once the summary's own status has moved past them (its line score is then final), and only when the play log and the line score agree on the side of the line (`periodDecision` in `src/agents/game-watch.js`). The last regulation period waits for the end of the game. On ESPN's final data the new rule matched Kalshi on all 46 of those markets where it made a call and declined 6. The 51 trades stay in the paper ledger as the losses they are. `COMPACT_VERSION` 5 makes the history test re-read its cached games, since they lacked line scores; its half and quarter results will now be decided at period ends, later and at worse prices than before.

**Exits and the circuit breaker.** A falling price never sells a game-watch position. On the Nov 4–7 sample (683 trades, +$33.25 held to settlement), every price stop cut profit: selling 5¢ below cost made 357 exits and −$52.52, 10¢ −$40.28, 20¢ −$25.30, 30¢ −$13.19, and 50¢ +$8.54; a 2¢, 5¢ or 10¢ price floor gave $31.27, $29.35 and $24.74. Every exited position would have won, since a decided market's bids thin out while it waits to settle (`scripts/replay-stop-loss.js`). A position is sold only when the thesis breaks: two fresh reads of the plays, at different times, decide the opposite side (`confirmOpposite` in `src/paper.js`), and the bid shows enough contracts to sell all of it after the fee (`exitQuote`). The breaker pauses a series and side for 24 hours after any loss or exit there, and gross losses reaching `--daily-loss` (game-watch $100, station-watch $25) in a rolling day stop new trades for 24 hours.

Quoting candidates require a certified series with settlement sources, focus membership, at least 500 daily contracts, positive depth, a 2–6 cent spread and enough lead before close or expected expiration to quote before the pre-game cutoff (at least two hours). Eligible markets come from the leagues in `mm.seriesPrefixes` (NFL, NBA, WNBA, NHL, MLB and the major European soccer leagues, cups and UEFA competitions, minus `mm.excludeSeriesPattern` second divisions), plus any other certified market ending within `mm.nearTermHours` (48). At most `mm.maxMarkets` (1,000; about 660 to 720 qualified on 2026-11-12) are recorded per scan, priority series first, then by volume. Quotes sit one cent inside the spread, skew by minus inventory times `mm.skewTicks`, stop at `mm.maxInventory` and pull `mm.pullMinutes` before close. A game market closes days after the game, so quoting also stops `mm.pullBeforeExpiryMinutes` (240) before the expected expiration: on 2026-11-08, quoting through live play turned a near-flat day into a $75 settled loss. A mid move of `mm.jumpHalt` (3 cents) between snapshots halts that market for good, and no quotes are posted while the mid sits outside `mm.minMid`–`mm.maxMid` (5–95 cents). Later opposing-price crossings simulate fills; maker fees follow series settings. Net P&L marks remaining inventory at its exit side (the bid for a long, the ask for a short) less the taker fee to flatten it, so an open position is never valued above what selling it would return. Settled markets are valued at their $1/$0 outcome, cached in `settlements.json`. The game-day loop also records public trade prints for the cohort every `mm.tradeSeconds` (60) into `trades.jsonl`, from one paced poll of Kalshi's exchange-wide trade tape (about 19 pages a minute, whatever the cohort size; prints outside the cohort are dropped); a seller at or below a resting model bid, or a buyer at or above its ask, fills that quote even when the next snapshot shows no crossed book. Series in `mm.prioritySeries` (pre-game NFL player props) fill the cohort first. The 15-minute markout is a separate adverse-selection diagnostic. Missing future observations are counted explicitly. Candidate filtering and sparse snapshots limit this research model; no queue, liquidation or incentives are simulated.

## Game-day loop

`node scripts/kalshi-gameday.js [--until=23:59|never] [--series=KXNBAGAME,...] [--out=data/gameday]` runs until the given local time, or with `never` until stopped. A full focus scan, including Polymarket auto-matching, starts every five minutes. Between full scans, up to 20 events are refreshed every 15 seconds using at most eight concurrent event reads. `gameday.fullMinutes`, `gameday.fastSeconds` and `gameday.watchSize` in `config/scan.json` control these settings; `--series` narrows full scans. In REST mode rounds never overlap, and an overlong round makes the next due round start immediately.

The watch list ranks each event's best eligible candidate by profit per basket contract, breaking ties by total event 24-hour volume. Candidates must pass every verification check. One closest negative taker ladder is retained per event when no below-par ladder exists, allowing eligible events to be watched before an edge appears. Fast rounds reuse the full scan's series map and matched cross-venue pairs, refreshing public metadata and books without new Polymarket searches. Failed event reads clear that event's old hits. A failed full REST scan clears its old hits; a failed background discovery scan preserves only signals owned by the functioning feed. Watched hit durations have roughly 15-second resolution when rounds finish on time.

The output directory holds open hits in `state.json`, closed episodes in `log.jsonl`, dry-run results in `dryrun.jsonl`, and one `rounds.jsonl` line per round with tier, timestamp, duration, event/candidate/hit counts, best profit per contract, errors and full-round watch-list tickers. New hits trigger the shared-budget dry run in a background child using a fixed hit snapshot. If a replay is already running, the round records `dryrunSkipped: true`. The loop reads public data only and places no orders. Use `--out=work/codex-gameday` for isolated test runs.

Each full scan also selects the market-making cohort (up to `mm.maxMarkets` quoting candidates). The loop re-reads the cohort every `gameday.fastSeconds` with one batched `GET /markets?tickers=` request per 50 markets and appends a book to `books.jsonl` when its prices change, and otherwise once a minute (89% of reads repeated the last prices), so model quotes stay inside `mm.maxQuoteAgeMs` (90 seconds). At each UTC day change the recordings move to `books-YYYY-MM-DD.jsonl` and `trades-YYYY-MM-DD.jsonl`. After each full scan, `scripts/kalshi-mm-sim.js` streams the last `mm.replayDays` (3) days of those files into `mm-sim.json`; the dashboard shows `data/maker/mm-sim.json` when present. Missing or inactive markets are left out of a snapshot rather than repeated.

The same replay also scores the learned quoting policy (`policy` in `src/bandit.js`, with the model `kalshi-bandit.js` saves as `data/history/bandit-model.json`), which declines the fixed rules' quotes where the history's closing-line value was negative. Its totals go to `mm-sim.json` as `learned`, beside the fixed rules' `total`, and both reach the quoting engine's heartbeat on the department pages. From Nov 12 the loop ran in the background as the quoting engine's paper loop, `node scripts/kalshi-gameday.js --until=never --out=data/maker`; since Nov 13 the dashboard's Start runs that same loop, so one loop feeds both the dashboard and the paper test. ## Live feed

`node scripts/kalshi-gameday.js --feed --out=work/codex-ws` uses production market data with `KALSHI_KEY_ID` and `KALSHI_KEY_PATH`. Kalshi requires authentication even for market-data WebSockets; a production API key must come from the user's own Kalshi account. Like the demo key, the production private key is stored outside the repository (for example `%USERPROFILE%\.kalshi\prod-key.pem`), so it cannot be committed; `KALSHI_KEY_PATH` is the feed's sole external file input. The feed only reads market data and never imports order functions.

`--feed=demo --out=work/codex-ws` uses `KALSHI_DEMO_KEY_ID` and `KALSHI_DEMO_KEY_PATH`, demo REST metadata and demo books. The explicitly authorized demo key path may be outside the repository. Demo prices serve plumbing tests only; demo mode skips cross-venue matching. Without `--feed`, or when the selected environment's credentials are missing, the CLI prints the reason and uses the REST fast tier.

Feed mode watches up to `gameday.feedWatchSize` events (default 300), ranked by the full scan. Top-of-book price or size changes reprice only their event, coalesced once per event-loop tick. Full scans run in a worker thread so basket enumeration does not block feed messages, and swap market subscriptions on completion. Feed-owned hits remain under scoped feed tracking; production cross-venue pairs retain Polymarket polling at `gameday.fastSeconds`. Every active market in an event must have a fresh snapshot before event pricing resumes after a reconnect or subscription-wide sequence gap. Gaps and disconnects immediately invalidate affected signals; dropping an event from the watch list clears its feed signals. Cross-venue comparisons read the latest Kalshi price again after the remote book requests finish. Reconnect delay doubles from one second to a 30-second cap.

Each minute, a `latency` round records receipt-to-result p50, p95 and max in milliseconds, sample count, cumulative feed message counts and watch size. If p95 exceeds `gameday.maxLatencyMs` (default 100 ms), capacity shrinks 20%, dropping the lowest-ranked events, with a minimum capacity of one so latency can still be measured. Capacity grows 10% per full scan, up to the configured maximum, while the latest measured p95 is below half the target; an empty measurement window does not cause growth. Final partial-minute statistics are logged at shutdown. No numeric market subscription limit was found in Kalshi's documentation; the feed uses one connection and one order-book subscription, and reports server subscription errors. Metadata and pair membership refresh on full scans. The feed imports no order client and sends only subscription commands.

## Verification and review

Verified candidates require a Kalshi product-certification URL, event settlement sources, at least 500 contracts of 24-hour volume on every Kalshi leg, matching close times, and more than two hours until the first close or expected expiration of any leg (a game already in play keeps a far close time, so its expected expiration is what flags it). The Verified column lists failed checks. `verified.reviewedSeries` records manual series review separately. Hits require verification; unverified candidates remain visible among misses. The dry run uses verification; any future live trading must require `verified && reviewed`, as well as separately approved execution and risk controls. Certification identifies a Kalshi-issued contract; it does not guarantee profit.

## Maker baskets

Maker variants rest the widest-spread leg at least one cent above its bid, rounded up to a whole-cent price below the ask and take the other legs only after a fill. The resting leg needs a non-zero bid and a spread of at most `makerMaxSpread` (default 4¢): on an empty or wide book such a bid fills only after the price has moved against it. Plain quadratic series have no maker fee; other series use `makerFeeRate` (0.0175, matching published secondary summaries of the Kalshi schedule) times their multiplier. The current maker fee list and liquidity-incentive rebates must be checked against [Kalshi fee schedule](https://kalshi.com/fee-schedule). Rebates are never counted as profit. These candidates are labelled **maker (needs a fill)**: a seller must hit the resting order, often just before an adverse price move. The basket dry run skips them.

Focus uses any matching prefix, tag, or category.

Lockup and annualized return use expected expiration, falling back to close time. Every candidate is capped at 60 days unless it yields at least $0.03 per basket contract and 10% annualized within 400 days; exceptions carry `longHold: true`. Close times still govern the close-time verification checks.

Automatic sports lookups skip games with no Kalshi leg meeting the volume requirement. Matches compare both team names (including league-scoped Polymarket team aliases) and UTC game date within one day. Only moneylines with compatible overtime or regulation rules qualify; unknown wording and ambiguous matches are skipped. [Kalshi basketball terms](https://assets.kalshi.com/contract_terms/BASKETBALLGAMEWIN.pdf) and [football terms](https://assets.kalshi.com/contract_terms/FOOTBALLGAMEWIN.pdf) include overtime by default for full games. Soccer requires regulation wording; fights require explicit matching draw/no-contest half payouts. Automatic pairs remain `autoMatched: true, reviewed: false`, never enter `config/pairs.json`, and need manual confirmation before live use. Both venues must also settle a cancelled or postponed game the same fixed way (Yes, No or 50-50); a Kalshi "fair price" or unstated terms reject the pair. On 2026-11-07 two EFL League One draw pairs priced at a 16% return failed exactly here: Polymarket resolves the draw market Yes if the game does not start, Kalshi pays a fair price, and Polymarket traders priced the draw at 97% a week out, consistent with an expected postponement. Auto matches remain research candidates; the cancellation check reads wording and is no substitute for manual review. Public lookups share a five-request-per-second limit. Discovery metadata is cached, but market status and order books share only in-flight requests and refresh after each completed read. Failed requests can be retried; errors are recorded while Kalshi scanning continues.

The basket dry run checks only hits that are new in the latest scan, so a persisting hit is replayed once. It funds verified taker hits best-annualized first, with a shared $1,000 bankroll, $100 per event, one basket per event, and at most 20 events (`budget`). Resized order fees are recomputed, the largest affordable whole-contract size is selected, and both minimum profit and minimum return must still hold after resizing. A rejected size leaves the budget available for other events. All funded hits share one delay deadline; up to eight Kalshi reads run concurrently with HTTP 429 backoff. Cross-venue research plans also recheck Polymarket acceptance and public books. Reads remain concurrent; hypothetical fills reserve shared Kalshi-side or Polymarket-token depth in funded order, so two baskets cannot claim the same shares. A failed fill-or-kill leg consumes no depth. Older hits missing exact per-leg costing are skipped and need a fresh scan; proportional scaling of historical rounded fees is not permitted. Skipped hits record their reason in `dryrun.jsonl`. Limits describe one simultaneous replay batch; no persistent live positions or funds are managed.

## Pricing safeguards

Ladder comparisons require one recognizable strike comparison in the primary rules. Only that strike and equivalent repeated comparisons in secondary rules are masked; dates, player identifiers, periods, close times and expected expirations remain part of the identity. Integer sports wording such as “at least 30 goals” is recognized for a strict 29.5 strike. Missing or ambiguous rules are skipped. Text matching remains a research aid rather than a substitute for manual settlement review.

The slippage buffer is one **cent** per configured `slippageTicks`, including markets with subcent prices. Its cost bound may reach $1 and never reduces an observed price above 99 cents. This is a conservative cost reserve; dry-run order limits remain at the observed price. Invalid or non-finite depth and negative fee multipliers are rejected. Polymarket dry-run checks aggregate available asks up to the order limit. Integer order sizes and Kalshi direct-member balance precision remain the accounting assumptions; fees use the series multiplier and no incentives are included.

## Performance and window lifecycle

A persistent EventSource connection identifies an open dashboard, including a minimized window. Timer throttling does not expire the engine session. After the last window disconnects, a 20-second reconnect grace period applies; Stop remains immediate. The scripts launcher also stops its owned server when the app window closes. Opening the dashboard never starts scanning.

The equity desk provides Today and All recorded views with realized, unrealized and net simulation P&L and isometric SVG equity bars. Realized P&L uses average entry cost on closed inventory and expenses all fees when incurred. Unrealized P&L marks remaining inventory at sampled market midpoints. Their sum reconciles to the simulator's cash-plus-inventory equity. Daily figures are changes from the last mark before the America/Los_Angeles calendar day, including transfers from unrealized to realized as positions close. Missing daily observations remain unavailable, not zero. All-time means the available simulator dataset; no live account ledger is connected. Chart observations carry timestamps and hover/focus details.

Regenerate the accounting history with `node scripts/kalshi-mm-sim.js`. Existing price-availability checks never count as realized profit.

## Daily strategy audit and quote validity

`node scripts/kalshi-day-review.js [YYYY-MM-DD]` streams public session recordings and writes a dated audit under `research/daily/`. The calendar uses America/Los_Angeles. Sources are reported independently to avoid treating duplicated archived checks as additional trades. Logged near misses are repeated shortlist observations, not a complete market sample. The daily model audit starts flat; the equity desk retains its historical opening-mark calculation.

Mutually exclusive No baskets test liquid subsets at up to eight depth breakpoints per event. At each breakpoint, fee-adjusted leg costs order the cheapest prefixes; the best verified return and the highest qualifying profit after the event budget are retained alongside the full subset. This can remove expensive legs that dilute return or consume the budget. Each alternative is repriced with its own contract count, payout and fees; only one basket per event can be allocated. This bounded search is not exhaustive subset optimization. Canonical ticker ordering keeps candidate identities stable when quote rankings change.

Removing an outcome preserves the at-most-one-winner lower bound: No on k selected outcomes pays at least k - 1 even if an excluded outcome wins. The fast watch list ranks taker candidates, since hypothetical maker savings require an unobserved seller and are not directly replayable. An ineligible below-par ladder no longer prevents the same event's closest verified ladder from entering discovery.

Model quotes now expire after `mm.maxQuoteAgeMs` (30 seconds). A sparse later book cannot imply a fill against an expired quote. A whole-contract simulated fill also requires at least one contract of opposing displayed depth; fractional depth cannot be promoted to a whole fill. Posting requires `mm.minQuoteEdge` (half a cent) after the estimated one-contract maker fee, and locked quotes are rejected. This is a conservative modeled spread floor, not a measured profit guarantee. Fifteen-minute markouts require an observation within `mm.maxMarkoutDelayMs` (90 seconds since Nov 12) after the horizon. Missing marks remain unmarked. Expired intervals are counted explicitly. Sparse data may produce no inferred fills; a zero modeled P&L in that case is not evidence of profitability.
